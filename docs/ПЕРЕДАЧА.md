## С чего начать

```bash
python -m venv .venv
.venv/bin/python -m pip install torch torchvision
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m pytest          # 106 тестов, меньше секунды, без сети и нейросетей
```

Если тесты зелёные — окружение собрано верно. Дальше прогон:

```bash
.venv/bin/python run_batch.py --input <папка с кадрами> --output results/batch --no-vlm
```

На macOS перед первым запуском может понадобиться
`export SSL_CERT_FILE=$(python -c "import certifi;print(certifi.where())")` — иначе не скачаются
модели.

## Как мерить качество

Единственный честный способ, которым пользовались здесь: прогнать 25 кадров и сверить
`detections.json` с эталонной разметкой `eval/ground_truth.json` из соседнего решения команды.
Считать **не «сколько номеров показано», а «сколько показано верно»**: верные, неверные,
выдуманные, пропущенные.

Важно про эталон: он сделан не организаторами, а другой нейросетью по этим же кадрам. Три
спорных случая проверены глазами — разметка оказалась права, ошибалась наша система. Мерить
по ней можно, но помнить о происхождении стоит.

## Чего делать не надо

Всё это уже пробовали и отказались по результатам замера, подробности в `docs/ИТОГИ.md`:

- **обучать модель на датасете** — в нём нет разметки, учиться не на чем;
- **поднимать PostgreSQL** — в проекте нет нагрузки, где он что-то даёт, а точка отказа
  на защите появляется;
- **расширять рамку номера вбок** — замер: ноль новых верных, один новый неверный;
- **возвращать формат номеров 1993 года** — перехватывал верные прочтения;
- **копировать датасет на сервер** — он уже в `/data` и не расходует диск команды.
