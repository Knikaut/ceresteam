## Шаг 1. Доступ без пароля (делает человек, один раз)

Сервер пускает только по паролю, а для работы нужен ключ:

```bash
ssh-keygen -t ed25519 -f ~/.ssh/hackathon -N ""
ssh-copy-id -p 2226 -i ~/.ssh/hackathon.pub team@149.137.233.66
```

Вторая команда один раз спросит пароль. После этого: `ssh -p 2226 -i ~/.ssh/hackathon team@149.137.233.66`.

## Шаг 2. Главная проверка: встанут ли зависимости на Python 3.14

Это **основной риск всего переезда**, и проверяется он за пятнадцать минут. Версия очень свежая,
и готовых сборок под неё может не быть.

```bash
cd /workspace
git clone -b fix/plates-batch-corrections https://github.com/Knikaut/ceresteam.git
cd ceresteam
python -m pip install --user --dry-run -r requirements.txt
```

Пины `torch==2.5.1` и `torchvision==0.20.1` в `requirements.txt` рассчитаны на Python 3.12
и под 3.14 не соберутся — torch с поддержкой 3.14 начинается с 2.14. На сервере torch уже
стоит системный, поэтому ставим всё остальное без него:

```bash
grep -v "^torch" requirements.txt > /tmp/req.txt
python -m pip install --user -r /tmp/req.txt
```

**Если что-то не встанет** (вероятнее всего `easyocr` или `opencv-python-headless`) — поднять
свой Python 3.12 в `/workspace` через micromamba, root для этого не нужен:

```bash
curl -Ls https://micro.mamba.pm/api/micromamba/linux-64/latest | tar -xvj bin/micromamba
export MAMBA_ROOT_PREFIX=/workspace/mamba
./bin/micromamba create -y -p /workspace/py312 -c conda-forge python=3.12
```

## Шаг 3. Проверка на пяти кадрах и замер видеокарты

```bash
python run_batch.py --input /data/Auto --output /workspace/results/smoke \
    --limit 5 --device cuda --no-vlm
```

Что смотрим:
- **сколько секунд на кадр** (на Apple M4 было 5 с; на видеокарте ожидаем 1–2 с);
- **сколько места занял результат** — умножьте на 22 140 и сравните с 59 ГБ;
- отработал ли `--device cuda` или система откатилась на процессор (она пишет об этом сама).

Если модели не скачались — на сервере нужен интернет для первого запуска; проверить
`curl -sI https://github.com` и при необходимости задать `SSL_CERT_FILE`.

## Шаг 4. Ограничить сохранение картинок (обязательно до полного прогона)

Замер на маке: результат одного кадра весит около 1,8 МБ, из них 1,5 МБ — размеченный кадр.
На 22 140 кадрах это **примерно 40 ГБ из 59 доступных**. В задании требуется «несколько
изображений с отмеченными объектами», а не все двадцать две тысячи.

Нужна правка в `run_batch.py`: флаг вида `--annotate-every N` или «сохранять размеченный кадр
только там, где прочитан номер». Работы на полчаса, делать **до** полного прогона.

## Шаг 5. Полный прогон

```bash
nohup python run_batch.py --input /data/Auto --output /workspace/results/auto \
    --device cuda --no-vlm > /workspace/auto.log 2>&1 &
```

Прогон переживает обрыв связи и продолжается с места остановки при повторном запуске.
Следить: `tail -f /workspace/auto.log`. Ошибки кадров — в `results/auto/errors.jsonl`.

Оценка времени: при 1,5 с на кадр — около 9 часов на 22 тысячи. **Параллелить сильно не
получится: на сервере всего 2 процессорных ядра**, а подготовка изображений упирается в них,
а не в видеокарту. Разумно два процесса, не больше.

Для остальных каталогов (`Сорняки`, `ФотоПолей`) — тот же прогон с `--recursive`, но сначала
стоит понять, что мы от них хотим: задание про технику, а не про сорняки.

## Шаг 6. Марка и модель

Сейчас без ключа к облачной модели марка определяется у одной машины из 29. Два пути:

1. **Классификатор по внешнему виду** из соседнего решения команды (`project/agro_alpr/classify.py`):
   сравнивает вырезку машины с текстовыми описаниями марок СНГ, ничего не обучает, работает
   офлайн. По замеру соседнего проекта — 17 угаданных марок из 20. Перенести так же, как
   перенесли распознаватель номеров.
2. **Локальная модель, описывающая фото словами** — на 16 ГБ видеопамяти помещается модель
   на 7 миллиардов параметров. Это **запуск готовой модели, а не обучение**: обучать не на чем,
   в датасете нет разметки.

Начинать с первого: он дешевле, быстрее и уже измерен.

## Чего на сервере делать не надо

- **Обучать модель.** В датасете нет подписей «это КАМАЗ-65115», учиться не на чем.
  Разметить самим и учиться на своих же псевдо-подписях — значит выучить чужие ошибки.
- **Поднимать PostgreSQL.** Разбор показал: в проекте нет нагрузки, где он что-то даёт,
  зато появляется лишняя точка отказа на защите.
- **Копировать датасет в `/workspace`.** Он уже в `/data` и не расходует ваш диск.
