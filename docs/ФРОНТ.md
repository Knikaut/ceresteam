# Интерфейс весовой: ручки API и что доделать

Документ для того, кто делает интерфейс. Серверная часть готова и покрыта тестами, формат
ответов обратно совместим — нынешний интерфейс продолжает работать.

Сервер отдаёт JSON по адресу `http://127.0.0.1:8000`. Ошибки приходят как `{"detail": "текст"}`
с кодами 400, 404 или 500. Текст ошибки написан по-человечески и его можно показывать как есть.

## Кто этим пользуется

Это стоит держать в голове при вёрстке.

**Весовщица** на складе: женщина 40+, весь день на ногах, в вагончике весовой, иногда в перчатках.
Экран — старый монитор или дешёвый планшет, часто 1366×768 при укрупнённом масштабе Windows,
свет бьёт в экран. Компьютером пользуется уверенно на уровне «1С и WhatsApp». Ошибка в данных
означает спор с водителем и недостачу зерна.

**Руководитель**: мужчина 40+, смотрит с телефона или ноутбука, вникать в детали не будет.
Ему нужно «что происходит сейчас» и «где проблема».

## Действующие ручки

| Ручка | Что делает | Что принимает | Что возвращает |
|---|---|---|---|
| `GET /api/state` | всё состояние для экрана руководителя и списка кадров | — | `vehicles[]`, `warehouses[]`, `on_territory`, `camera`, `server_time` |
| `GET /api/messages` | лента чата весовщицы | — | массив сообщений |
| `GET /api/vehicles/{id}` | карточка машины | `id` — бортовой номер, например `3` | `{vehicle, trips[], messages[]}` |
| `GET /api/warehouses/{id}` | карточка склада | `id` — `W1`…`W4` | сводка + `trips[]` + `messages[]` |
| `POST /api/camera/capture` | взять следующий необработанный кадр | `{"frame": "18.jpg"}` или пустое тело | `{capture_id, file, url, frame}` |
| `POST /api/upload` | загрузить своё фото | файл формой `multipart/form-data` | то же, что у `capture` |
| `POST /api/report` | анализ снимка и оформление заезда или выезда | `capture_id` обязателен; `driver`, `crop`, `warehouse_id`, `weight`, `note`, `plate_override` — по желанию | `{guard_message, ai_message}` |
| `POST /api/reset` | стереть базу демонстрации | — | `{"ok": true}` |
| `GET /frames/{имя}` | исходный кадр из папки камеры | — | картинка |

Порядок работы: `camera/capture` или `upload` даёт `capture_id`, затем с этим `capture_id` уходит
`report`. Обработка занимает около 10 секунд на кадр, и сервер обрабатывает строго один снимок
за раз — вторая отправка ждёт в очереди.

## Что изменилось в `POST /api/report`

**Повторная отправка того же снимка больше не создаёт второй рейс.** Если связь оборвалась и
весовщица нажала «Отправить» ещё раз, сервер вернёт прежний результат и добавит в ответ
`"duplicate": true`. Это значит, что нужно не «отправить заново», а просто показать полученный ответ.

**В `ai_message.payload` появились поля:**

```json
{
  "event_kind": "entry",
  "weight": 19.57,
  "weight_source": "не измерен: придуман демо-генератором, весы не подключены",
  "weight_measured": false,
  "alerts": ["Склад не выбран — записан Склад №1 · Элеватор"],
  "plate": {
    "formatted": "041 AHF 10",
    "source": null,
    "ocr": { "readable": true, "confidence": "высокая", "alternatives": [] }
  },
  "recognized_by_appearance": null,
  "vehicle": { "id": "1", "label": "№1 · МАЗ МАЗ-5516" },
  "trip": { "id": 1, "status": "open", "entry_weight": 19.57 }
}
```

- `weight_measured` — `false`, если вес придумал генератор. **Это надо показывать:** сейчас
  выдуманное число выглядит на экране как показание весов, и им спорят с водителем.
- `plate.ocr.confidence` — «высокая», «средняя» или «низкая». Сервер считает и отдаёт это давно,
  но интерфейс не показывает.
- Если номер прочитан ненадёжно, поля номера **пустые**, а догадка распознавания лежит отдельно
  в `license_plate.ocr_guess` внутри отчёта. Её нельзя показывать как номер — только как подсказку.
- `recognized_by_appearance` — машина узнана не по номеру, а по цвету. Это **рискованное**
  состояние, его нельзя красить в зелёный.

## Новые ручки: отмена и правка

Раньше любая ошибка была необратима — единственной кнопкой был «Сброс демо», стирающий всю смену.

### `GET /api/events/last`

Последнее оформленное событие — чтобы заполнить форму правки. Пустой объект, если событий нет.

```json
{
  "event": { "id": 3, "kind": "exit", "created_at": "2026-09-18 03:27:50" },
  "trip": { "id": 1, "status": "closed", "entry_weight": 19.57, "exit_weight": 12.5 },
  "vehicle": { "id": "1", "label": "№1 · МАЗ МАЗ-5516", "plate_formatted": "041 AHF 10" },
  "kind_ru": "выезд",
  "weight": 12.5,
  "weight_source": "введён вручную",
  "ai_message_id": 4
}
```

### `POST /api/events/last/undo`

Отменяет последний заезд или выезд. Рейс возвращается в прежнее состояние: отменённый выезд снова
открывает рейс, отменённый заезд удаляет его. Кадр снова становится доступен в очереди камеры.

```json
{ "ok": true, "undone": "exit", "trip_id": 1, "ai_message": { "text": "Выезд отменён. Рейс №1 снова открыт…" } }
```

Если отменять нечего — код 404.

### `PATCH /api/events/last`

Исправляет последнее событие. Все поля необязательны, передавайте только изменённые.

```json
{ "plate": "384 CBA 10", "driver": "Петров", "crop": "Ячмень", "weight": "18.5" }
```

Ответ содержит журнал изменений — его удобно показать прямо в чате:

```json
{
  "ok": true,
  "changes": [
    { "field": "номер", "was": "041 AHF 10", "now": "384 CBA 10" },
    { "field": "водитель", "was": "Иванов", "now": "Петров" }
  ],
  "trip": { "id": 1 },
  "vehicle": { "id": "1" },
  "ai_message": { "text": "Исправлено: …" }
}
```

Негодный вес (`nan`, ноль, отрицательный, неправдоподобно большой) отклоняется кодом 400
с понятным текстом. Правки остаются в журнале события — видно, что и когда исправили.

## Что обязательно доделать в интерфейсе

По убыванию важности. Первые три — то, из-за чего на складе будет скандал.

1. **Пометить выдуманный вес.** Если `weight_measured: false`, рядом с числом нужна явная пометка
   вроде «вес не измерен». Сейчас генератор и настоящие весы выглядят одинаково.
2. **Кнопки «Отменить» и «Исправить»** у последнего события в чате. Сейчас исправить нельзя ничего:
   ошиблась один раз — живи с этим до сброса всей смены.
3. **После обрыва связи — не «отправить заново», а показать результат.** Сервер сам отличает
   повтор (`duplicate: true`), но кнопка не должна подталкивать весовщицу плодить рейсы.
4. **Показывать уверенность номера** и варианты прочтения из `plate.ocr`. «Узнана по внешности»
   и «номер из профиля» — жёлтым, а не зелёным: номер на кадре не прочитан.
5. **Честный индикатор связи.** Сейчас при обрыве продолжает гореть «LIVE» и «Система активна»,
   а на экране висят замороженные цифры. Два неудачных опроса подряд — красная полоса
   «нет связи, данные от 14:32».
6. **Человеческие тексты ошибок** вместо системных окон. Сейчас вылезает
   «Ошибка обработки: Ошибка обработки: cannot identify image file» и английское «Failed to fetch».
   Сервер уже отдаёт нормальный текст в `detail` — достаточно показать его.
7. **Размеры и контраст.** Замерено в браузере: кнопка «Снимок с камеры» 146×31 пикселя при шрифте 12,
   поля ввода 38, выбор кадра 28. Нужно 44–48 пикселей и шрифт полей 16–18. Контраст чипа с номером
   2,86 к 1 при норме 4,5 — на бликующем экране не читается.
8. **Подписи у полей и пометка обязательных.** Сейчас только серые подсказки внутри поля: заполнила —
   и уже не понять, где что. Проверка сообщает об ошибках по одной.
9. **1366×768 при укрупнённом масштабе** ломает вёрстку: страница уходит в прокрутку, одно сообщение
   ИИ занимает весь чат. Это типичный складской монитор.
10. **Экран руководителя.** На карте только склады, машин нет. Ответа на «где сейчас проблема» нет:
    тревоги считаются по всем рейсам, включая закрытые, поэтому склад краснеет навсегда. Нужна лента
    активных тревог и отметка рейсов, висящих дольше смены. На телефоне 390 пикселей карточка машины
    разваливается: значение «Госномер» оказывается в колонке шириной 33 пикселя.
11. **«Сброс демо»** стоит в 8 пикселях от «Сменить роль», защищён одним «Вы уверены?» и стирает всё.
    Нужны подтверждение посерьёзнее и выгрузка смены перед стиранием.

## Что уже сделано хорошо и лучше не ломать

- Роли действительно разделены: у весовщицы одна колонка без карт и списков.
- Двойное нажатие заблокировано, снимок и введённые поля не теряются при ошибке.
- Enter переводит между полями, а не отправляет форму; после снимка фокус встаёт в «Фамилию».
- Обработанные кадры помечаются галочкой.
- Поиск понимает и кириллицу, и латиницу в номерах, и «№12» как бортовой номер.
- Номер показывается крупно рядом с кадром — прочтение можно проверить глазами.
- Тревоги дублируются значком, а не только цветом. Весь вывод экранируется.

## Чего в системе нет и не будет к защите

Чтобы не рисовать в макете то, чего не существует:

- **Настоящих весов.** Вес либо вводит человек, либо его придумывает генератор.
- **Марки и модели без ключа к облачной модели.** На прогоне 25 кадров без неё марка нашлась
  у одной машины из 29.
- **Прицепа, гружёного кузова и «заезжает пустой»** — эти три проверки тоже работают только
  с этим ключом.
- **Складов.** Их названия и координаты выдуманы.
