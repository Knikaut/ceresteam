# Весовая AI — техника и госномера на весовой

Решение **задания 2 хакатона «Техника и государственные номера»**. По фотографиям с камеры весовой
программа находит технику, читает госномер Казахстана, определяет тип техники, производителя и модель,
сохраняет результат в JSON и CSV и рисует рамки на кадрах.

Поверх обязательной части сделано рабочее место весовой. Весовщик получает снимок машины в чате с ИИ,
вписывает фамилию водителя и культуру, система оформляет заезд и выезд и ловит подозрительные рейсы.
Руководитель видит машины и склады на карте.

## Как закрыты пункты задания

| Пункт задания | Как решено | Где в результатах |
|---|---|---|
| 1. Найти технику на фотографиях | YOLOv8s: грузовики, легковые, автобусы и люди; самая крупная техника считается стоящей на весах | `detections[].category = vehicle`, рамка `bounding_box_px`, `on_scale` |
| 2. Распознать госномер, если он есть и читается | EasyOCR: первый проход по вырезке машины, затем каждая область-кандидат читается ещё несколькими способами (увеличение, контраст, ч/б) — на кадр уходит 14–26 вызовов распознавания. Прочтения голосуют и проверяются по шаблонам номеров РК. **Ненадёжное прочтение не выдаётся за номер:** поля пустые, `readable: false`, догадка распознавания лежит отдельно в `ocr_guess` | `license_plate`, отдельная рамка `category = license_plate`, `N_plate.jpg` |
| 3. Определить тип техники | VLM уточняет тип до «самосвал / бортовой грузовик / седельный тягач / трактор / прицеп…»; без VLM — класс детектора | `equipment_type` |
| 4. Производитель и модель | По приоритету: реестр **data.egov.kz** по госномеру → надпись на технике (OCR) → VLM. Страна производителя — по справочнику марок | `manufacturer`, `model`, `year`, `manufacturer_country`, `manufacturer_confidence` |
| 5. JSON/CSV и изображения с отмеченными объектами | `run_batch.py` пишет общий `detections.json` и `detections.csv`, отчёт по каждому кадру и картинки с рамками | `results/batch/` |

**Результат на датасете (25 кадров, OpenRouter `anthropic/claude-sonnet-5`):**
- техника на весах найдена на **25 из 25** кадров;
- уточнённый тип техники — **25 из 25**;
- производитель — **21 из 25**;
- модель — **17 из 25**;
- страна производителя — **21 из 25**;
- госномер уверенно прочитан — **10 из 25** (на остальных номера нет, он закрыт или слишком мелкий);
- время с надписи камеры — **10 из 25**.

```bash
python -m venv .venv
```
```bash
.venv\Scripts\python -m pip install torch torchvision
```
```bash
.venv\Scripts\python -m pip install -r requirements.txt
```

На Linux/macOS вместо `.venv\Scripts\python` пишите `.venv/bin/python`. Веса YOLO (~22 МБ) и модели EasyOCR
(~110 МБ) скачиваются сами при первом запуске, поэтому **первый запуск требует интернета**.

**Видеокарта.** По умолчанию устройство выбирается само: NVIDIA, если она есть, иначе процессор.
Переопределяется переменными окружения `OCR_GPU` (распознавание текста) и `YOLO_DEVICE` (детектор),
у пакетного прогона — флагом `--device`. Значения: `auto`, `cpu`, `cuda`, `mps`. Если видеокарта
отвалится посреди прогона, обработка продолжится на процессоре, а не упадёт.

Для NVIDIA ставьте torch под свою версию CUDA, например:
`pip install torch torchvision --index-url https://download.pytorch.org/whl/cu130`.

**Сертификаты на macOS.** Python с python.org ставится без корневых сертификатов, и тогда модели
не скачиваются. Лечится запуском «Install Certificates.command» из папки Python либо переменной
`SSL_CERT_FILE=$(python -c "import certifi;print(certifi.where())")`.

**Ключ для VLM (рекомендуется).** Скопируйте `.env.example` в `.env` и впишите ключ OpenRouter:
```
OPENROUTER_API_KEY=sk-or-v1-...
```
Без ключа программа тоже работает, но тип, марку и модель определит только по реестру и надписям на технике.

## 1. Пакетная обработка папки — обязательная часть задания

```bash
.venv\Scripts\python run_batch.py --input "/data/Auto" --output results/batch
```

| Флаг | Что делает |
|---|---|
| `--input` | папка с кадрами (по умолчанию `DATA_DIR`) |
| `--output` | папка результатов (по умолчанию `results/batch`) |
| `--limit N` | обработать только первые N кадров |
| `--recursive` | обойти и подпапки (`Auto`, `Сорняки`, `ФотоПолей`) |
| `--force` | пересчитать кадры, по которым отчёт уже есть |
| `--merge-only` | только собрать `detections.json` и `.csv` из готовых отчётов |
| `--device` | устройство детектора: `auto`, `cuda`, `mps`, `cpu` |
| `--no-vlm` | не обращаться к VLM |
| `--no-registry` | не искать номер в data.egov.kz (без сети) |

Что появится в папке результатов:
- `detections.json` — все кадры одним файлом;
- `detections.csv` — одна строка на каждый найденный объект: кадр, категория, тип, производитель, страна, модель, год, уверенность в марке, номер, формат и регион номера, цвет, загрузка, прицеп, рамка, уверенность;
- `N.json` — отчёт по кадру `N.jpg`, он же отметка «кадр посчитан»;
- `N_annotated.jpg` — кадр с рамками: красная — техника, жёлтая — номер, зелёная — человек;
- `N_plate.jpg` — номер крупно, чтобы человек мог проверить прочтение;
- `N_vehicle.jpg` — вырезка машины;
- `errors.jsonl` — журнал кадров, которые не удалось обработать.

Обработка занимает около 10 секунд на кадр на процессоре (замерено на Apple M4: 25 кадров за 255 с,
самый долгий кадр 22 с). С видеокартой заметно быстрее.

**Прогон рассчитан на полный датасет организаторов — 22 140 кадров, это часы работы:**
- кадр с готовым отчётом пропускается, поэтому после обрыва прогон продолжается с того же места;
- битый или нечитаемый кадр не роняет прогон: он попадает в `errors.jsonl`, остальные считаются;
- прерывание с клавиатуры собирает итоговые файлы из уже посчитанного;
- итоговые `detections.json` и `.csv` собираются потоком с диска, память не растёт с числом кадров;
- при `--recursive` путь к кадру попадает в имя отчёта, иначе `Auto/1.jpg` затрёт `Сорняки/1.jpg`.

Размеченные кадры занимают около 1,5 МБ каждый: на полном датасете это примерно 40 ГБ.
Учитывайте это, если диск ограничен.

## 2. Веб-интерфейс весовой

```bash
.venv\Scripts\python -m backend.main
```

Откройте http://127.0.0.1:8000 и выберите роль. Выбор запоминается в браузере, поменять его можно кнопкой «Сменить роль».

### Весовщик — только чат с ИИ

1. «📷 Снимок с камеры» — берётся следующий необработанный кадр из папки камеры. Можно выбрать кадр в списке или загрузить своё фото.
2. Снимок прикрепляется к сообщению сам. Обязательно впишите **фамилию водителя** и **культуру**, выберите склад. По желанию укажите вес, исправленный номер (если ИИ ошибся) и заметку.

   **Про вес.** Настоящих весов в демо нет. Если поле пустое, число придумывает генератор, и это
   видно и в ответе ИИ, и в выгрузке: рядом с весом всегда написано, откуда он взялся —
   «введён вручную» или «не измерен: придуман демо-генератором». Спорить с водителем можно
   только по первому.
3. «Отправить». Через 10–30 секунд ИИ отвечает:
   - кадр с рамками и номер крупно;
   - бортовой номер машины (`№1 · МАЗ 5551`), тип, производитель со страной, модель, год;
   - статус проверки номера в реестре data.egov.kz;
   - **заезд** (открыт рейс, брутто) или **выезд** (тара, нетто, рейс закрыт);
   - предупреждения;
   - ссылки на `detections.json` и `detections.csv`.
4. Когда та же машина снова встаёт на весы, система узнаёт её по номеру (или по внешности, если номер не читается) и закрывает рейс как выезд.

Если обработка упала, в чате появится сообщение об ошибке, а снимок можно отправить повторно:
**повторная отправка того же снимка не создаёт второй рейс** — сервер вернёт уже готовый ответ.

### Исправление ошибок

Ошибку системы можно отменить или поправить, не стирая смену:

- **отменить последний заезд или выезд** — рейс возвращается в прежнее состояние, кадр снова
  становится доступен в очереди камеры;
- **исправить последнее событие** — госномер, фамилию водителя, культуру и вес. Прежние значения
  остаются в журнале правок, то есть видно, что и когда исправили.

Ручки API — в разделе «API для интерфейса». Кнопок в нынешнем интерфейсе пока нет, они делаются
вместе с новым макетом.

### Руководитель — машины и карта

- Слева — список машин с бортовыми номерами и поиском по номеру (`№3`), госномеру или марке. Клик по машине открывает карточку: фото, данные, все рейсы, события с камер.
- Справа — карта (спутник Esri / схема OpenStreetMap) со складами и числом машин на каждом. Клик по складу показывает, кто сейчас на складе, последний заезд и выезд, рейсы и события с камер.
- «Сброс демо» очищает базу.

Предупреждения, которые выдаёт система:
- выезд тяжелее заезда (если брутто на заезде неизвестно, вместо тревоги пишем, что нетто не посчитано);
- на выезде кузов гружёный **(только с ключом к облачной модели)**;
- на заезде был прицеп, на выезде его нет **(только с ключом к облачной модели)**;
- выезд через другую весовую;
- склад не выбран или неизвестен — раньше он молча становился «Складом №1»;
- слишком быстрый оборот (меньше 3 минут);
- рейс был открыт дольше смены — обычно это пропущенный выезд;
- время выезда раньше времени заезда (сбиты часы камеры) — проверяется, только когда оба времени
  сняты с надписи камеры;
- машина заезжает пустой **(только с ключом к облачной модели)**;
- номер не прочитан или сопоставлен по внешности;
- вес не разобран как число, бесконечность, ноль, отрицательный или неправдоподобно большой.

Три предупреждения опираются на описание внешности от облачной модели. **Без ключа они не
срабатывают вовсе** — это не поломка, но и не контроль.

Файлы веб-режима: `results/captures/` (снимки), `results/reports/<снимок>/` (кадр с рамками, JSON, CSV),
база `results/weighbridge.db`.

## API для интерфейса

Сервер отдаёт JSON по адресу `http://127.0.0.1:8000`. Полное описание с примерами ответов и
списком того, что нужно доделать в интерфейсе, — в [docs/ФРОНТ.md](docs/ФРОНТ.md).

| Ручка | Что делает |
|---|---|
| `GET /api/state` | всё состояние: машины, склады, очередь кадров |
| `GET /api/messages` | лента чата весовщицы |
| `GET /api/vehicles/{id}` | карточка машины: данные, рейсы, события |
| `GET /api/warehouses/{id}` | карточка склада |
| `POST /api/camera/capture` | взять следующий кадр из папки камеры |
| `POST /api/upload` | загрузить своё фото |
| `POST /api/report` | анализ снимка и оформление заезда или выезда |
| `GET /api/events/last` | последнее оформленное событие — для формы правки |
| `POST /api/events/last/undo` | отменить последний заезд или выезд |
| `PATCH /api/events/last` | исправить номер, водителя, культуру, вес |
| `POST /api/reset` | стереть базу демонстрации |

Три последние ручки новые. `POST /api/report` теперь возвращает `duplicate: true`, если тот же
снимок отправили повторно, и не создаёт второй рейс.

## Реестр офлайн

Чтобы во время демонстрации не зависеть от интернета, набор data.egov.kz скачивается один раз:

```bash
python tools/fetch_registry.py --out data/registry/registered_vehicles.jsonl
```

Это 24 759 записей, около 5 МБ. Дальше поиск по номеру идёт по этому файлу, в сеть система
не ходит. Снимок ищется в `data/registry/`, затем в `RESULTS_DIR/registry/`; путь можно задать
переменной `REGISTRY_SNAPSHOT`.

Портал отдаёт по 20 записей за запрос и **ограничивает обращения сорока в минуту**, поэтому
полная выкачка занимает около получаса. Пауза между запросами уже выставлена с запасом,
уменьшать её нельзя. Источник данных обязателен к упоминанию: интернет-портал «Открытые данные»
Республики Казахстан, data.egov.kz, набор «Зарегистрированные транспортные средства».

Набор неполный — это регистрации 2022 года, и номеров с кадров весовой в нём нет. Он нужен как
проверка «номер существует в реестре РК», а не как источник марки для этих кадров.

## Как это работает

1. **Детекция.** YOLOv8s находит технику и людей. Рамки тягача и кузова одной машины склеиваются.
   **На весах стоит ровно одна машина** — самая крупная на кадре. Техника сопоставимого размера рядом
   тоже разбирается (номер, марка), но помечается `on_site`, а не `on_scale`: иначе прицеп попадал
   в отчёт отдельной машиной на платформе.
2. **Номер.** OCR читает всю вырезку машины. Каждую область, похожую на номер, система увеличивает и читает ещё три раза: как есть, с усиленным контрастом и в чёрно-белом варианте. Прочтения голосуют и проверяются по шаблонам номеров РК.

   Чтобы система не выдумывала номера, действуют четыре правила:
   - при подгонке под шаблон разрешено исправить **не больше двух символов** и не больше одной
     замены цифры на букву. Без этого ограничения номером становилась почти любая строка из
     семи символов, включая дату с надписи камеры: `05-06-2019` превращалось в `050 GZO 19`;
   - строки, похожие на дату и время, отбрасываются до разбора;
   - кириллическая буква без латинского двойника (З, Г, Ф) **отвергает строку целиком**.
     Раньше она просто выбрасывалась, и `041 АНГ 10` превращалось в `041 AH 10` — номер другой машины;
   - прочтение ниже порога надёжности не показывается как номер: поля пустые, а догадка лежит
     в `ocr_guess` как подсказка охраннику.

   Поддержанные форматы: `041 AHF 10`, `681 AS 10`, `98 AAH 10`, номер краской на борту `10 625 AZ`
   и старый образец до 2012 года `P 523 AFE`.
3. **Реестр.** Номер ищется в открытом наборе data.egov.kz «Зарегистрированные транспортные средства».
   Если рядом лежит скачанный снимок набора, поиск идёт по нему, **без обращения в интернет**
   (см. раздел «Реестр офлайн»). Статус проверки пишется в `registry_status`:
   - `found` — марка, модель и год взяты из реестра;
   - `not_found` — номера нет в наборе;
   - `unavailable` — нет сети и нет снимка, повторная попытка через 60 секунд;
   - `disabled` — реестр выключен.
4. **VLM.** Один запрос на кадр, только по машине на весах. Возвращает тип, производителя, модель, страну, цвет, загрузку, прицеп и описание внешности. Номер у VLM не спрашиваем: его читает OCR. Если VLM называет другого производителя, чем реестр или надпись, её модель не записывается, а расхождение попадает в `notes`.
5. **Страна производителя** определяется по справочнику марок (МАЗ → Беларусь, КамАЗ → Россия, Shacman → Китай…), иначе берётся оценка VLM.
6. **Память системы** — база SQLite. Каждая машина получает бортовой номер по порядку: он выдаётся
   системой, вписать его нельзя. Повторный приезд узнаётся по госномеру или по цветовому отпечатку.
   Отпечаток — это цветовая гистограмма вырезки, поэтому машина узнаётся, только если она заметно
   похожее остальных кандидатов; при равном сходстве система честно не узнаёт машину, а не
   приписывает рейс чужой. Эталонный отпечаток не перезаписывается кадром, опознанным лишь
   по внешности. Модель ничего не дообучает.
7. **Время события** помечается источником: надпись камеры или системные часы. Сравниваются только
   времена одного источника — на части кадров часы камеры показывают 2019 год, и смесь источников
   давала тревогу «выезд раньше заезда» почти на каждом выезде.

### Стоимость

VLM через OpenRouter стоит около 0,5 цента за кадр для `anthropic/claude-sonnet-5`, то есть примерно 13 центов на
25 кадров. Ответы кэшируются в `results/vlm_cache.json`, поэтому повторный прогон тех же кадров бесплатен.
Остальные компоненты (YOLO, EasyOCR, реестр, карта) бесплатны.

## Ограничения

- Камера широкоугольная, номер на кадре занимает 50–100 пикселей. OCR путает похожие буквы. Система
  скорее откажется читать номер, чем покажет выдуманный: ненадёжное прочтение уходит в `ocr_guess`,
  а номер вводит человек.
- **Марка и модель без ключа к облачной модели почти не определяются.** На прогоне 25 кадров без неё
  марка нашлась у одной машины из 29 — по надписи «Кировец» на кабине. Всё остальное в полях
  производителя и модели приходит от платного запроса к Claude.
- **Три предупреждения из десяти работают только с этим же ключом:** прицеп, гружёный кузов
  на выезде, «заезжает пустой». Без ключа они молчат.
- **Узнавание «по внешности» — это сравнение цветов**, а не распознавание машины: цветовая
  гистограмма вырезки вместе с куском фона. Две белые фуры на одной площадке похожи почти одинаково,
  поэтому система требует заметного отрыва от второго кандидата и при сомнении не узнаёт машину.
- **Весы имитированы полностью.** Подключения к настоящим весам нет ни одного: вес либо вводит
  человек, либо его придумывает генератор. Источник всегда написан рядом с числом.
- Открытый набор data.egov.kz неполный: около 25 тысяч машин, зарегистрированных в 2022 году.
  Номеров из датасета хакатона в нём нет, поэтому на этих кадрах он подтверждает только сам факт
  проверки, а марку не даёт.
- На части кадров сбиты часы камеры (2019 год при летней траве). Время берётся с надписи как есть,
  но помечается источником, и времена из разных источников между собой не сравниваются.
- Склады, их названия и координаты — выдуманы.
- На весах считается ровно одна машина. Техника рядом разбирается, но помечается как стоящая
  вне платформы; техника на заднем плане отмечается рамкой без чтения номера.
- Датасет организаторов в репозиторий не включён: на кадрах реальные номера. Ссылку дают организаторы.
